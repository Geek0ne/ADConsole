# AD 域控管理控制台

提供两个版本：

- **WPF 正式版**（推荐）：`ADConsoleWpf\bin\Release\ADConsole.exe`，纯 LDAP/ADSI，不依赖 RSAT
- **PowerShell 轻量版**：`ADConsole.ps1`，基于 WinForms + RSAT ActiveDirectory 模块

## WPF 正式版

| 项目 | 说明 |
|---|---|
| 源码 | `ADConsoleWpf\`（.NET Framework 4.8，旧式 csproj） |
| 程序 | `ADConsoleWpf\bin\Release\ADConsole.exe`（x64） |
| 构建 | 用 `Framework64\v4.0.30319\MSBuild.exe` 执行 `/t:Rebuild /p:Configuration=Release /p:Platform=x64`；改代码后请先删 `obj`、`bin` 再重建 |
| 测试 | `test-adconsole-wpf.ps1`，**214 / 214 全部通过** |

功能要点：

- **登录框**：记住密码 / 自动登录；凭据用 Windows DPAPI（CurrentUser）加密存于
  `%APPDATA%\ADConsole\credential.dat`，换账户或换机器无法解密
- **权限徽标**：按 `tokenGroups` 的组 SID 判定「域管理员 / 委派管理员 / 只读」，
  并按真实用户 DN 查询（用户不在 `CN=Users` 时同样正确）
- **写操作门禁**：只读账户的修改/删除/重置密码等菜单自动禁用；所有写操作均由用户主动触发
- **右键编辑属性**：可修改用户的部门 / 职位 / 邮箱 / 电话 / 说明
- **性能**：登录时先把域服务器解析为 IPv4 并固定走同一台 DC，避免 LDAP 主机名解析和
  DC 自动发现造成的 20 秒级卡顿；主窗口先显示，权限、OU 树、对象列表在后台加载
  （实测：点击登录到主窗口约 0.5–0.7 秒，列表首行约 1.3–1.5 秒）

## PowerShell 轻量版

基于 **PowerShell + WinForms + RSAT ActiveDirectory 模块**，单文件实现，无需编译。
以下为 PowerShell 版的说明。

## 文件

| 文件 | 说明 |
|---|---|
| `ADConsole.ps1` | 主程序（约 1600 行） |
| `启动AD控制台.bat` | 双击启动器（自动处理 STA 线程与执行策略） |

## 启动

**方式一**：双击 `启动AD控制台.bat`（推荐）

**方式二**：命令行

```powershell
powershell.exe -NoProfile -STA -ExecutionPolicy Bypass -File .\ADConsole.ps1
```

> 程序已内置 STA 自检：若当前会话不是 STA 线程，会自动以 `-STA` 重新拉起。
> 源文件必须保存为 **UTF-8 with BOM**，否则 Windows PowerShell 5.1 会按 ANSI(GBK) 读取，
> 中文字符串会被破坏并产生大量解析错误。

## 界面结构

```
菜单栏   文件 / 用户 / 组 / 计算机 / 工具 / 帮助
工具栏   刷新 | 对象类型(用户/组/计算机) | 搜索框 | 位置显示
┌────────────┬──────────────────────────────┐
│  OU 树     │  对象列表（详细信息视图）      │
│            ├──────────────────────────────┤
│            │  属性面板（属性 / 值）        │
└────────────┴──────────────────────────────┘
状态栏   查询统计 | 当前域账号
```

## 功能

### 浏览
- **OU 树**：域根 + 全部 91 个 OU + 常用容器（Users / Computers / System 等），容器节点显示为灰色
- **对象列表**：用户 / 组 / 计算机，点击树节点切换
- **属性面板**：选中任意对象即显示其 DN、状态、部门、密码状态、创建时间等

### 查询规则
- 选中 **OU/容器** → 列出其**直接子对象**（OneLevel）
- 选中 **域根** → **递归列出全域对象**（因用户实际存于 `CN=Users`、计算机存于 `CN=Computers`，并非域根直属）
- 搜索框**有内容** → 在当前节点子树内**递归搜索**（支持姓名、登录名、邮箱）

### 用户管理
- 新建用户（姓名 / 登录名 / UPN / 初始密码 / 部门 / 职位 / 邮箱 / 电话 / 描述）
- 重置密码（支持随机生成 16 位强密码，符合复杂度要求）
- 启用 / 禁用 / 解锁账号
- 删除用户、查看属性

### 组管理
- 新建组（安全组 / 通讯组，全局 / 域本地 / 通用）
- 添加成员（弹出搜索选择器）、移除成员（多选）
- 查看成员（含嵌套成员，可导出 CSV）

### 计算机管理
- 查看 / 启用 / 禁用 / 删除

### 工具
- **域信息与密码策略**：FSMO 五角色、全局编录、DNS 服务器、密码长度与复杂度、锁定策略（可一键复制）
- **导出 CSV**：当前列表导出为 UTF-8 CSV
- 右键菜单：复制 DN、按模式删除等

## 环境要求

- Windows PowerShell **5.1**（非 PowerShell 7 —— WinForms + AD 模块组合按 5.1 验证）
- **RSAT ActiveDirectory 模块**（已验证可用）
- 已加入目标域（当前环境：`example.com`，PDC `AD.example.com`）

## 权限说明

| 操作 | 所需权限 |
|---|---|
| 浏览、查询、搜索、查看属性、域信息 | 普通域账号即可（`EXAMPLE\user1` 已验证） |
| 新建 / 修改 / 删除对象、重置密码、启停账号 | 需要相应**委派权限**或域管理员 |

写操作失败时会弹出错误对话框并显示 AD 返回的具体原因（如 `INSUFFICIENT_ACCESS_RIGHTS`），
不会静默失败。

## 开发过程中修复的真实缺陷

1. **`OuMap` 误写成数组 `@()`** —— 而非哈希表 `@{}`，导致树构建时 `InvalidCastFromStringToInteger` 直接崩溃
2. **域根显示 0 个对象** —— AD 中用户位于 `CN=Users` 容器，按 OneLevel 查询必然为空；改为域根递归
3. **`Get-ADGroup` 默认不返回 `whenCreated`** —— 139 个组全为 `$null`，`.ToString()` 抛异常后弹出 MessageBox 等待点击，表现为"程序挂死"；已补 `-Properties whenCreated` 并加空值守卫
4. **菜单栏停靠到工具栏下方** —— WinForms 按添加顺序反向分配边缘，调整了 `Controls.Add` 顺序
5. **源文件无 BOM** —— UTF-8 无 BOM 被 PowerShell 5.1 按 GBK 读取，产生 60+ 个假解析错误

## 注意事项

- **写操作未在生产域实测**。读取路径已全量验证；新建/删除/重置密码等写操作请先在测试账号或测试 OU 上验证。
- 删除操作有二次确认，但**不可恢复**。
- 组成员查询使用 `-Recursive`，超大组（数千成员）会稍慢。
- 全域搜索上限 500 条（用户选择器内）。
